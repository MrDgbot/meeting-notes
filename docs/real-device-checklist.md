# 真机验收清单（iPhone / iPad / 安卓）

模拟器和无头浏览器测不到的部分，要在真设备上按这个清单走一遍。每一项都写了怎么做、预期结果、要记下什么。记下的结果补进 `docs/mobile-evidence.md` 的“真机”一节。

准备：
- Mac 上打开“设置 · 平板、手机访问”，设好口令并打开开关。
- 手机连同一个 Wi-Fi，**用相机或 Safari 扫码，不要用微信扫**。
- 记下设备型号、系统版本、浏览器版本。

## A. 录一场会（最重要）

| # | 怎么做 | 预期 | 记下 |
|---|---|---|---|
| A1 | 不装证书：扫码 → 点“显示详细信息 → 访问此网站” → 登录 → 新建会议 → 开始录音，说几句话 | 两种结果都可能：实时文字正常出现；或者提示“实时转写连接失败……要先安装并信任 Mac 的证书” | 出现的是哪一种 |
| A2 | 装证书：登录页“下载证书” → 设置里安装描述文件 → “通用 → 关于本机 → 证书信任设置”里打开开关 → 刷新 | 地址栏不再显示“不安全”，录音时实时文字正常 | 是否正常 |
| A3 | 录音中关掉 Wi-Fi 30 秒再打开 | 断开时出现黄色提示“和 Mac 的连接断开了……已暂存 N 秒”；恢复后提示“已补传”；结束后会议头部显示“录音完整（断网重连 1 次，已补传）” | 头部显示的文字 |
| A4 | 同上，断开 2 分钟 | 同 A3 | 同上 |
| A5 | 录音中按电源键锁屏 10 秒，再解锁回到页面 | 两种结果都可能：没有缺口（Safari 在后台继续收音）；或者提示“刚才 N 秒没录到：页面在后台或锁屏了”，转写稿里有标记 | 出现的是哪一种，缺口秒数和实际锁屏时间差多少 |
| A6 | 录音中切到别的应用 20 秒再切回 | 同 A5 | 同 A5 |
| A7 | 录音中让别人打个电话进来，接听 10 秒后挂断 | 记一个“被系统打断”的缺口；回来后如果顶上提示“现在录不到声音”，点“继续录音”能恢复 | 要不要点“继续录音” |
| A8 | 录音中连上 / 断开 AirPods | 断开时如果麦克风断了，会出现“麦克风断开了”和“重新连接麦克风”按钮 | 实际现象 |
| A9 | 插电，屏幕朝上放在桌子中间，连续录 2 小时；记下开始和结束的时间 | 屏幕不自动锁上；结束后头部“录音完整”；会议时长 + 缺口合计 ≈ 实际经过的时间（相差 ≤ 2 秒） | 电量变化、机身温度、会议时长、实际时长 |
| A10 | 同一场会，Mac 也同时录一份。你校对其中 3 段、每段 2 分钟的标准文本 | 用 `.venv/bin/python tests/audio/cer.py 标准文本.txt <会议ID> --from mm:ss --to mm:ss` 分别算 Mac 和 iPhone 的 CER，iPhone 不比 Mac 高 3 个百分点以上 | 两边的 CER |
| A11 | 只有 A10 不达标时做：在 `static/app.js` 的 `MIC_OPTS` 里把降噪、自动增益关掉再录一次 | 远处的人声识别变好，或者没有变化 | 两次的 CER |

## E. 不知情用户

请一个没接触过这个项目的人从扫码开始，不提供任何帮助，你在旁边计时、记下卡住的地方：
- 第一次使用（含装证书）完成登录并开始录音：目标 ≤ 10 分钟。
- 第二次从打开页面到开始录音：目标 ≤ 30 秒。
