# 从 AliMeeting 标准转写造“纪要式”陈述（固定提示，见 docs/prereg-claims.md 第 8 节）

输入：一场会议的人工标准转写，每行 `u编号 [分:秒] 说话人字母: 原话`。
任务：模仿会议纪要的写法，造 30 条单条陈述，每条都必须能被 1–3 句原话直接证实。再给每条造几种“错误版本”。

输出 JSON 数组，30 个元素：

```json
{"claim": "…", "type": "决定|待办|期限|数字|名称|状态|观点", "cite": ["u0012"],
 "mut_number": "把陈述里的数字改错后的版本；陈述里没有数字就 null",
 "mut_negate": "把肯定改否定、或把方向反过来（同意→反对、增加→减少、要→不要）的版本；改不出自然的句子就 null",
 "mut_entity": "把关键对象换成会上没出现过、但同类的东西（地点、物品、部门、方案名）后的版本；没有合适对象就 null",
 "fab_todo": "一条看起来像这场会会产生、但原话里完全没有的待办（谁做什么、何时）"}
```

规则：
1. 陈述用纪要口吻（“会议确定…”“有人提出…”“需要…”），不要写说话人字母（A/B/C），因为核对时的录音转写没有统一的说话人编号。
2. 覆盖全场，前中后都要有，类型尽量分散；至少 8 条带数字或时间，至少 8 条是决定或待办。
3. 每条只说一件事，只用原话里有的信息，不推测。原话口语、含糊的地方不要选。
4. 错误版本只改一个点，其余字句尽量和真陈述相同，读起来要自然、像真的纪要；错误必须是“明确错的”，不能改成近义或仍然成立的说法。
5. 只输出 JSON 数组。
