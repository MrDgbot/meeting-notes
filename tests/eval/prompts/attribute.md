# 错误归因（固定提示，见 docs/prereg-claims.md 第 5 节）

输入：若干条已经被判为“与原话矛盾 / 找不到依据 / 张冠李戴”的纪要陈述，每条标明它的纪要所依据的那一列转写（“依据列”），后面附证据窗口（多引擎转写，读法同 judge.md）。

对每条，按顺序判断，取第一个成立的：
1. **说话人**：依据列里相关内容在，但说话人编号或归属不对（与陈述所写的人不符，或依据列把话记到了别人名下，而纪要照抄）。
2. **识别**：依据列里相关的字本来就错了，而其他厂商的引擎多数一致地给出另一种说法；纪要照着依据列的错字写。
3. **检测**：依据列在相关时间里没有这段话（空着或缺句），但其他引擎有。
4. **大模型**：依据列是对的（或与多数引擎一致），纪要却写错、编出或概括失真。
5. **判不了**：信息不足以区分以上几种。

另外判断：如果“纪要写对了、是我们的裁判上一步判错了”（比如上一步没注意到某个窗口里的内容），填 “复核：有依据”。

输出 JSON 数组，与输入顺序一致：
```json
{"id": "陈述编号", "stage": "说话人|识别|检测|大模型|判不了|复核：有依据", "basis_quote": "依据列里相关的原文（不超过60字，没有就空）", "majority_quote": "其他厂商多数的说法（不超过60字）", "reason": "不超过80字"}
```
