# 漏写核对（固定提示，见 docs/prereg-claims.md 第 6 节）

两位标注员（甲、乙）各自独立地从同一段会议的多引擎转写里，提取了会上的决定和待办。你拿到的是：
- 这段会议的证据窗口，读法同 judge.md 的“证据怎么读”；
- 甲的清单（编号 A0、A1…）和乙的清单（编号 B0、B1…）；
- 两份会议纪要，记为“纪要X”和“纪要Y”。它们覆盖整场会议，不只是这一段。

按下面三步做。

1. **配对**：找出甲和乙指的是同一件事的条目，即同一个决定或同一个待办，说法可以不同，一条最多配一条。只有一方提到的不要。
2. **核实**：对每一对，回到证据窗口确认会上确实这么说了，关键处按跨厂商多数为准。确实说了的记“有依据”，否则记“不成立”。
3. **查纪要**：对“有依据”的每一对，分别在纪要X和纪要Y里找有没有写到：
   - **写到**：这件事写进去了，意思一致；负责人和期限如果原话里有，纪要也有；
   - **部分写到**：事写进去了，但缺了原话里有的负责人或期限，或者写得含糊到看不出要做什么；
   - **没写到**：纪要里找不到这件事；
   - 纪要写了但写错了的（人、数、方向不对），记“写到”，并在 note 里说明。写错由另一个环节专门判，这里只管有没有写。

后果（这件事如果纪要没写，会造成什么）：
- **严重**：有明确负责人或期限的待办，或者定了方向、数字的决定，漏了会让人不去做、做错或错过；
- **一般**：其他实质性的决定或待办；
- **轻微**：细枝末节，漏了影响不大。

只输出 JSON 数组，每一对一条。没有配对就输出 []：
```json
{"a": "A3", "b": "B5", "what": "一句话概括这件事", "real": "有依据|不成立", "windows": ["W0123"],
 "X": "写到|部分写到|没写到|不适用", "X_quote": "纪要X里对应的原文（不超过60字，没有就空）",
 "Y": "写到|部分写到|没写到|不适用", "Y_quote": "纪要Y里对应的原文（不超过60字）",
 "severity": "严重|一般|轻微", "note": "不超过60字"}
```
“不成立”的条目，X 和 Y 都填“不适用”。
